==========================================================
A. PERSIAPAN
==========================================================

ALUR HEMAT WAKTU (ujian 2,5 jam):
- Install Ubuntu dengan adapter Host-only (mode offline, tidak ada
  update otomatis, jadi lebih cepat).
- Setelah install selesai, ganti adapter ke Bridged lalu minta IP lewat
  netplan (langkah 0a sampai 0e di bawah).

0a. Matikan VM, ubah adapter jaringan:
    VirtualBox > Settings > Network > Adapter 1
    - Enable Network Adapter : dicentang
    - Attached to            : Bridged Adapter
    - Name                   : kartu jaringan fisik yang terhubung kabel ke ether2
                               (yang sama dengan yang dipakai laptop host)
    - Advanced > Promiscuous Mode : Allow All
    - Advanced > Cable Connected  : dicentang
    Lalu nyalakan VM.

0b. Lihat nama interface dan file netplan:
    ip a
    ls /etc/netplan
    (nama interface biasanya enp0s3, catat nama yang tampil.
     Nama file biasanya 50-cloud-init.yaml atau 00-installer-config.yaml)

0c. Edit file netplan (sesuaikan nama file dan nama interface):
    sudo nano /etc/netplan/50-cloud-init.yaml

    OPSI A - minta IP otomatis dari DHCP router (disarankan):
    ----------------------------------------------------
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: true
    ----------------------------------------------------
    Syarat: static lease di router sudah mengikat MAC VM ini ke 10.10.14.13
    (lihat langkah 8 di file network). IP yang didapat harus 10.10.14.13.

    OPSI B - IP manual (cadangan kalau DHCP tidak jalan, tidak bergantung MAC):
    ----------------------------------------------------
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses:
        - 10.10.14.13/28
      routes:
        - to: default
          via: 10.10.14.1
      nameservers:
        addresses: [10.10.14.1, 8.8.8.8]
    ----------------------------------------------------
    Kalau memakai Opsi B, kecilkan pool DHCP di router supaya tidak memberi
    10.10.14.13 ke perangkat lain:
    /ip pool set pool-server ranges=10.10.14.2-10.10.14.12

    Aturan penulisan YAML:
    - Indentasi memakai SPASI, bukan Tab.
    - Jumlah spasi harus rapi (kelipatan 2) dan sejajar seperti contoh.
    - Ganti enp0s3 dengan nama interface dari ip a.

0d. Terapkan:
    sudo chmod 600 /etc/netplan/*.yaml
    sudo netplan apply

    Kalau ingin aman terhadap salah ketik, pakai: sudo netplan try
    (tekan Enter untuk menerima; kalau tidak, otomatis kembali).

0e. Cek hasil:
    ip a                  (harus muncul 10.10.14.13/28 di interface bridged)
    ping -c 3 10.10.14.1  (router)
    ping -c 3 8.8.8.8     (Internet)

    Kalau belum dapat IP:
    - Pastikan adapter VirtualBox Bridged ke NIC yang benar (langkah 0a).
    - Cek nama interface di file netplan sama dengan di ip a.
    - Cek di router: /ip dhcp-server lease print
    - Kalau IP yang didapat bukan 10.10.14.13 (misal .12), MAC VM tidak
      sama dengan static lease. Perbarui di router:
      /ip dhcp-server lease remove [find comment=VM-Server]
      /ip dhcp-server lease add address=10.10.14.13 mac-address=MAC-VM server=dhcp-server-vm comment=VM-Server
      (MAC-VM: lihat ip link di VM, atau dari lease print di router)
      lalu di VM: sudo netplan apply
    - Kalau perintah "dhclient" tidak ada, pakai: sudo netplan apply

1. Cek IP server (harus 10.10.14.13):

   Jawaban:

   Change root password?                 N
   Remove anonymous users?               Y

C. WEB SERVER (Apache + PHP)
==========================================================

11. Install:
    sudo apt install apache2 php libapache2-mod-php php-mysql -y
    sudo systemctl enable --now apache2

12. Buat file koneksi database:
    sudo nano /var/www/html/database.php

    Isi:
    ----------------------------------------------------
<?php
$host = "localhost";
$user = "kafka";
$password = "UkomDB@2026";
$database = "ukom14";

$conn = new mysqli($host, $user, $password, $database);

if ($conn->connect_error) {
    die("Koneksi database gagal: " . $conn->connect_error);
}

echo "<h1>Koneksi Database Berhasil</h1>";

$result = $conn->query("SELECT * FROM informasi");

if ($result && $result->num_rows > 0) {
    while ($row = $result->fetch_assoc()) {
        echo "<hr>";
        echo "ID: " . htmlspecialchars($row["id"]) . "<br>";
        echo "Nama: " . htmlspecialchars($row["nama"]) . "<br>";
        echo "Keterangan: " . htmlspecialchars($row["keterangan"]) . "<br>";
        echo "Dibuat: " . htmlspecialchars($row["created_at"]) . "<br>";
    }
} else {
    echo "Tidak ada data.";
}

$conn->close();
?>
    ----------------------------------------------------

13. Restart dan tes dari server:
    sudo systemctl restart apache2
    curl http://localhost/database.php

    Harus muncul "Koneksi Database Berhasil" beserta 4 data.

G. DNS SERVER (bind9)
==========================================================

Tujuan: pada nslookup, baris "Server:" menampilkan nama server
(ns1.ukom12tkjkafka-14.sch.id), dan jawabannya langsung dari server Ubuntu.

URUTAN KERJA (jangan dibalik):
1. Konfigurasi bind9 di server (G1 sampai G6)
2. Tes dengan dig di server (G7) sampai semua hasil benar
3. BARU ubah DNS di DHCP router (G8)
Kalau DHCP diarahkan ke server sebelum bind9 berjalan, client kehilangan DNS
dan server tidak bisa apt install.

Catatan: router TIDAK memakai DNS static. Semua client (ether2, ether3,
dan hotspot) memakai bind9 di server ini sebagai DNS.

G1. Install:
    sudo apt install bind9 bind9utils dnsutils -y

G2. Opsi umum:
    sudo nano /etc/bind/named.conf.options

    Isi (ganti seluruh isinya):
    ----------------------------------------------------
options {
    directory "/var/cache/bind";
    listen-on { 127.0.0.1; 10.10.14.13; };
    allow-query { 127.0.0.1; 10.10.14.0/28; 100.100.14.0/30; 192.168.14.0/24; };
    recursion yes;
    allow-recursion { 127.0.0.1; 10.10.14.0/28; 100.100.14.0/30; 192.168.14.0/24; };
    forwarders { 8.8.8.8; 1.1.1.1; };
    dnssec-validation no;
};
    ----------------------------------------------------

G3. Daftarkan zona:
    sudo nano /etc/bind/named.conf.local

    Isi:
    ----------------------------------------------------
zone "ukom12tkjkafka-14.sch.id" {
    type master;
    file "/etc/bind/db.ukom12tkjkafka-14";
};

zone "14.10.10.in-addr.arpa" {
    type master;
    file "/etc/bind/db.10.10.14";
};
    ----------------------------------------------------

G4. Zona forward (nama ke IP):
    sudo nano /etc/bind/db.ukom12tkjkafka-14

    Isi:
    ----------------------------------------------------
$TTL 604800
@   IN  SOA ns1.ukom12tkjkafka-14.sch.id. admin.ukom12tkjkafka-14.sch.id. (
            1       ; Serial
            604800  ; Refresh
            86400   ; Retry
            2419200 ; Expire
            604800 ) ; Negative TTL
@   IN  NS  ns1.ukom12tkjkafka-14.sch.id.
@   IN  A   10.10.14.13
ns1 IN  A   10.10.14.13
www IN  A   10.10.14.13
    ----------------------------------------------------

G5. Zona reverse (IP ke nama, ini yang membuat "Server:" tidak UnKnown):
    sudo nano /etc/bind/db.10.10.14

    Isi:
    ----------------------------------------------------
$TTL 604800
@   IN  SOA ns1.ukom12tkjkafka-14.sch.id. admin.ukom12tkjkafka-14.sch.id. (
            1
            604800
            86400
            2419200
            604800 )
@   IN  NS  ns1.ukom12tkjkafka-14.sch.id.
13  IN  PTR ns1.ukom12tkjkafka-14.sch.id.
    ----------------------------------------------------

G6. Cek konfigurasi, jalankan, dan buka firewall:
    sudo named-checkconf
    sudo named-checkzone ukom12tkjkafka-14.sch.id /etc/bind/db.ukom12tkjkafka-14
    sudo named-checkzone 14.10.10.in-addr.arpa /etc/bind/db.10.10.14
    sudo systemctl enable --now bind9
    sudo systemctl restart bind9
    sudo ufw allow 53

    Tiga perintah cek harus tanpa error (zona menampilkan OK).
    Kalau systemctl tidak mengenali bind9, pakai nama: named

G7. Tes dari server sendiri:
    dig @10.10.14.13 ukom12tkjkafka-14.sch.id +short
    dig @10.10.14.13 -x 10.10.14.13 +short
    dig @10.10.14.13 google.com +short

    Hasil yang benar:
    10.10.14.13
    ns1.ukom12tkjkafka-14.sch.id.
    (IP Google)

G8. Di router - arahkan DNS DHCP ke server (setelah G7 benar semua).
    Ini sama dengan langkah 13 di file network:
    /ip dhcp-server network set [find address=10.10.14.0/28] dns-server=10.10.14.13
    /ip dhcp-server network set [find address=100.100.14.0/30] dns-server=10.10.14.13
    /ip dhcp-server network set [find address=192.168.14.0/24] dns-server=10.10.14.13

    Firewall: router tidak memakai firewall filter (hanya NAT), jadi tidak
    ada rule yang perlu ditambah untuk DNS.

G9. Tes dari laptop:
    ipconfig /release
    ipconfig /renew
    ipconfig /flushdns
    nslookup ukom12tkjkafka-14.sch.id

    Hasil yang diharapkan:
    Server:  ns1.ukom12tkjkafka-14.sch.id
    Address: 10.10.14.13

    Name:    ukom12tkjkafka-14.sch.id
    Address: 10.10.14.13

    (Screenshot ini untuk kategori 1)

G10. Kembali ke DNS router (kalau ada masalah):
    /ip dhcp-server network set [find address=10.10.14.0/28] dns-server=10.10.14.1
    /ip dhcp-server network set [find address=100.100.14.0/30] dns-server=100.100.14.1
    /ip dhcp-server network set [find address=192.168.14.0/24] dns-server=192.168.14.1
    (Internet tetap jalan, tetapi domain tidak ter-resolve tanpa bind9.
     Untuk sementara pakai file hosts di bawah.)

Kalau browser tidak mau resolve domain:
- Matikan Secure DNS/DoH di browser.
- Cadangan: edit file hosts. Buka Notepad dengan Run as administrator,
  buka C:\Windows\System32\drivers\etc\hosts, tambahkan di paling bawah:
  10.10.14.13 ukom12tkjkafka-14.sch.id

Risiko:
- Kalau VM mati atau bind9 berhenti, client yang DNS-nya ke server
  kehilangan DNS. Saat tes, pastikan VM menyala.
- Perubahan G8 berlaku setelah client meminta IP ulang (renew).
